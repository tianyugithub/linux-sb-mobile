# LINUX SB 客户端知识库（给回帖用）

只写用户能公开知道的事实。密钥、Cookie、内网、签名、镜像 IP、脚本路径等一律不在这里。

## 项目是什么

- 名称：LINUX SB。仓库名 linux-sb-mobile。包名 `sb.linux.mobile`。
- linux.sb 社区的**第三方非官方** Android 客户端，和官网没有隶属关系。
- 开源许可 MIT。仓库：https://github.com/tianyugithub/linux-sb-mobile
- 发布页：https://github.com/tianyugithub/linux-sb-mobile/releases
- 技术栈：Expo 54 · React Native 0.81 · React 19。
- 站点没有公开 API。客户端和网页一样请求官方页面、解析 HTML，登录沿用官方账号会话。请求都用使用者自己的会话发往 linux.sb，不传到别的服务器。
- 目前只做了 Android 构建和验证。没有 iOS 包。安装只能下 GitHub Releases 里的 APK。
- 检查更新：设置 → 关于项目。有 APK 时可以在应用里下载并调起系统安装。

## 这个帖子在干什么

- 版块：错误地方。标题：APP客户端建议反馈帖。
- 请用 LINUX SB Android 客户端提**真实问题**或**对客户端有用的建议**。
- 够格的楼，楼主（AI）会点官网的「楼主认可」，红包按官网规则发放。
- 打招呼、纯领红包、空泛夸奖、跟本客户端无关的站务，不认可。
- 发帖人不能领自己的红包。同一用户多条被认可的回复，按官网规则有机会多次获得。

## 首页与帖子列表

- 底部首页可切换版块，排序：新评论、新帖子、精华、抽奖、发卡、足迹、申精。
- 每日热帖：首页可展开，数据来自官网首页，不另开页面。
- 帖子列表屏蔽：设置里按关键词、用户名或版块隐藏，规则会同步到 linux.sb 账号。

## 看帖与互动

- 正文：富文本、代码高亮、视频、图片、链接卡片。
- 楼层、盖楼、点赞、打赏（烧饼）、收藏、淘帖专辑、举报。
- 回帖 / 回复某人 / 编辑自己的楼；抽奖帖作者若开了验证，回帖要做人机验证。
- 精华：作者可申请加精；其他人可参与竞猜。竞猜理由 5～300 字，只能交一次，理由会变成一条评议回帖。
- 「回复可见」：发帖时可把一段正文设成回复后才看见。没有单独的「解锁」按钮，回帖成功后才会显示。
- 红包帖：领取动作就是回帖，**没有「抢红包」按钮**。现行规则常见是「楼主认可」：先进入待审核，楼主点认可后按规则发放。卡片文案以页面为准（剩余份数、认可条件、结算天数）。发帖人不能领。

## 发帖编辑器

- Markdown 和所见即所得两种模式，表情库、插图、全屏、草稿。
- 发帖工具条有「回复可见」。回帖框没有这一项（跟官网一样）。
- 发帖须知：新建主题时会先确认规范，设置里可改成不再提示。
- 图床：有官网上传权限就用官网；也可以自己填 Cloudflare R2。没有上传权限时，可用自己的 R2 插图。

## 账号与资产

- 登录（游客登录页有人机验证）。注册走官网。
- 我的：签到、我的主题 / 回帖 / 收藏 / 私信、积分、烧饼钱包、我的称号、淘帖专辑。
- 签到中心：连续天数、累计签到、日历和流水里筛出来的签到记录。
- 称号中心：抽取、合成、市场等，跟官网同一套。
- 用户榜单、邀请中心、认证中心、淘帖中心。
- 通知中心；私信支持引用。私信是短文本，没有发帖那种插图通道。
- 搜索：帖子、用户、版块。用户主页。

## 设置（用户能改的）

- 官网访问通道：DoH / 直连。国内默认 DoH。
- HTTP/3 优先：站内请求先走 QUIC，失败会回落。
- 外观深浅色、正文字号。
- 代码与 JSON：主题、字体、字号。
- 图床、帖子列表屏蔽、发帖须知提示、插件开关。
- 消息推送：新回复 / 提及 / 打赏走系统通知。OPPO / ColorOS 建议打开「忽略电池限制」，否则休眠后可能收不到。可发测试通知、跳转系统通知权限。
- 关于项目：版本、包名、技术栈、许可证、项目主页、检查更新。

## 插件

- 设置 → 插件。默认全关，数据只在本机算，不上传。
- 目前内置「饼友助手」（第三方：原作者豆包本包的干货助手，二开 Evander-8）：积分账本、称号合成统计、称号市场监控、幸运打赏估算。

## 已知限制（回答时可以承认）

- 依赖官网页面结构，官网改版后个别功能可能暂时对不齐，需要后续更新。
- 没有 iOS。
- 抽奖回帖验证、精华竞猜次数等，以官网页面为准，客户端不另造规则。
- 红包发帖表单若还停留在旧的「回帖字数 / 先到先得」选项，而主题页已经是「楼主认可 + 结算天数」，那是客户端还没跟上官网的真实缺口，算有效反馈。
- 主题页追加红包（topup）若 App 里没有入口，也是已知缺口。

## 回答时禁止写出来的

- Cookie、token、CSRF、密钥、密码、钥匙库、证书指纹。
- 本机文件路径、监控脚本、模型名称、内部实现细节。
- 服务器 IP、反代地址、钉扎地址、未公开的通道细节。
- 教人绕过人机验证、伪造请求、偷会话、破解签名。
- 其他用户的私信、邮箱、或任何非公开资料。
